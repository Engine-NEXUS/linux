## 1. Overview

NEXUS uses a **BERT-Mini** model (`google/bert_uncased_L-2_H-128_A-2`, ~4.4M parameters) for natural language understanding (NLU). The model classifies user commands into 52 intents and extracts slot values (e.g., app names, URLs, contacts) using BIO tagging.

The model is a **fallback** — the deterministic Rust parser (`intent_parser.rs`) handles most commands. The NLU model only kicks in when the deterministic parser can't match a command. This means:

- **Most commands work without the NLU model** (deterministic parser)
- **The NLU model improves coverage** for unusual phrasings, STT distortions, and new commands
- **Better training data → better fallback → fewer "unknown" commands**

### Two Commands for Contributors

| Command | Purpose | Time |
|---------|---------|------|
| `nexus collect` | Speak phrases → record → transcribe → save real voice samples | ~10-30 min |
| `nexus train` | Clean → generate → merge → train → export → sync → **cleanup** | ~5-15 min |
| `nexus build` | Bundle the new model into the installer.exe | ~5 min |

### Why Collect Real Voice Samples?

Synthetic data (generated by `generate_live_data.py`) covers many phrasings, but it misses:

- **Real STT distortions** — how Groq/Moonshine actually transcribes your speech
- **Pronunciation variants** — your accent, speed, and style
- **Filler words** — "um", "uh", "like", "so", "actually"
- **Microphone characteristics** — your mic's frequency response, noise floor
- **Room acoustics** — echo, background noise, distance from mic
- **Natural phrasing** — how you actually speak vs. how you think you speak

Real voice samples are the single most impactful thing you can add to improve NLU accuracy.

## 3. `nexus collect` — Voice Sample Collector

### What It Does

1. Shows you a phrase to say (e.g., "type hello world")
2. You press **Enter** when ready to speak
3. Countdown: 3...2...1...SPEAK! (big visible boxes)
4. Records 2 seconds of audio (16kHz mono, matching NEXUS runtime)
5. Transcribes the audio via:
   - **Groq cloud** (auto-loads API key from NEXUS `settings.json`) — preferred
   - **STT server** (port 39217, Moonshine) — fallback if Groq unavailable
6. Shows you what it heard
7. Auto-saves the transcript + intent + slots to a JSONL file
8. 1.5s gap, then shows the next phrase (press Enter when ready)
9. Press **Ctrl+C** at any time to stop — all collected samples are saved

### Usage

```bash
# Full collection — all 23 intents, 10 samples each (230 total)
# Press Enter → 3...2...1...SPEAK! → 2s record → save → gap → next
nexus collect

# Specific intent only
nexus collect --intent type_text

# More samples per intent
nexus collect --count 20

# List all available intents
nexus collect --list

# Text mode — no microphone (saves phrases directly)
nexus collect --text-only

# Combine flags
nexus collect --intent press_key --count 30
```

### Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--intent <name>` | all | Collect for a specific intent only |
| `--count <n>` | 10 | Number of samples per intent (1 collection = 10 samples) |
| `--list` | — | List all available intents and exit |
| `--text-only` | false | Save phrases directly (no recording) |

### Interactive Mode (Enter to Record)

The collector waits for you to press Enter before each recording:

```

  Say: "type hello world"
  Press Enter when ready to speak...
  ╔═══════╗
  ║   3   ║
```

- **10 samples per intent = 1 collection** (default `--count 10`)
- **1.5s gap** between each sample (time to breathe)
- **Press Enter** when ready — no rush, take your time
- **Ctrl+C** to stop anytime — all saved samples are kept

### Groq API Key Auto-Load

The collector automatically loads the Groq API key from:
1. `GROQ_API_KEY` environment variable (if set)
2. `%APPDATA%/com.nexus.assistant/settings.json` → `groqApiKey` (NEXUS settings)
3. `~/.config/com.nexus.assistant/settings.json` (Linux/macOS)

You don't need to set any environment variable — if you've configured Groq in NEXUS settings, the collector finds it automatically.

### Output File

```
server/admin/data/collected_samples.jsonl
```

Each line is a JSON object:

```json

  "text": "type hello world",
  "intent": "type_text",
  "slots": {"text": "hello world"},
  "source": "voice",
  "timestamp": 1789231579.45

```

| Field | Type | Description |
|-------|------|-------------|
| `text` | string | The transcribed text (what STT heard) |
| `intent` | string | The intended intent label (e.g., `type_text`) |
| `slots` | object | Extracted slot values (e.g., `{"text": "hello world"}`) |
| `source` | string | `"voice"` (recorded) or `"text"` (text-only mode) |
| `timestamp` | float | Unix timestamp of collection |

### Requirements

- **Python 3.12+** with `sounddevice`, `numpy`, `scipy` (auto-installed by `nexus collect`)
- **Working microphone** (built-in or USB)
- **Groq API key** — auto-loaded from NEXUS `settings.json` (no env var needed)
  - OR STT server running (`nexus start` runs it on port 39217)
  - OR `GROQ_API_KEY` environment variable set manually

### What Makes a Good Collection Session

- **Quiet room** — minimize background noise (TV, music, fans, other people)
- **Consistent distance** — stay 30-50cm from the microphone
- **Natural pace** — speak as you normally would to NEXUS, not slower or faster
- **Natural phrasing** — if the prompt says "type hello world" but you'd naturally say "type in hello world", say it your way — the STT transcript captures your real phrasing
- **Multiple sessions** — collect 10-20 samples per intent across 2-3 sessions (different times of day, different moods) for variety
- **Include errors** — if STT mishears you, keep the sample! The mishearing is valuable training data — it teaches the model what STT distortions look like

## 4. `nexus train` — Full Training Pipeline

### What It Does (8 Steps)

```
Step 1: Clean dataset
  → Fix malformed labels (OpenArchitect → open_architect)
  → Convert to lowercase
  → Deduplicate by (text, intent)

Step 2: Generate synthetic examples
  → Run generate_live_data.py
  → Produces ~1097 new examples across 11 live-mode intents
  → Includes STT distortions, filler words, negative examples

Step 3: Merge all data
  → Merge generated examples into dataset.json
  → Merge collected voice samples from collected_samples.jsonl
  → Deduplicate everything

Step 3b: Re-clean after merge
  → Fix any new malformed labels
  → Remove duplicates introduced by merge

Step 4: Train BERT-Mini
  → Load google/bert_uncased_L-2_H-128_A-2 (4.4M params)
  → Fine-tune for 50 epochs on CPU
  → Joint intent classification + slot filling
  → Class-weighted loss to handle imbalance
  → Save best_model.pt (best validation accuracy)

Step 5: Export to ONNX
  → Load best_model.pt
  → Export to nexus_nlu.onnx (16.8 MB, max_length=64)
  → Save labels.json (intent + slot label lists)

Step 6: Sync to resources
  → Copy nexus_nlu.onnx → src-tauri/resources/server/nlu/model/
  → Copy labels.json → src-tauri/resources/server/nlu/model/
  → Copy tokenizer/ → src-tauri/resources/server/nlu/model/
  → Ready for `nexus build` to bundle into installer

Step 7: Audit the trained dataset and ONNX model
  → Verify all intent labels and slot annotations
  → Detect conflicts, duplicates, and train/test leakage
  → Measure intent accuracy, slot exact match, false slots, and targeted OOS behavior
  → Write audit_report.json and docs/research/nlu-model-data-audit-latest.md

Step 8: Clean up temporary files (save ~17 MB disk space)
  → Delete new_examples.json (150 KB, merged into dataset.json)
  → Delete model/best_model.pt (17 MB, ONNX is the production format)
  → Delete collected_samples.jsonl (merged into dataset.json)
  → Keep: dataset.json, nexus_nlu.onnx, labels.json, tokenizer/
```

### Usage

```bash
# Full pipeline (clean → generate → merge → train → export → sync → cleanup)
nexus train

# Just clean the dataset (fix labels, deduplicate)
nexus train --clean-only

# Everything except training (data refresh only)
nexus train --skip-train

# Keep temporary files (for debugging — adds ~17 MB)
nexus train --keep-temp
```

### Files Deleted After Training

| File | Size | Why Delete? |
|------|------|-------------|
| `server/nlu/new_examples.json` | ~150 KB | Generated synthetic data, already merged into `dataset.json` |
| `server/nlu/model/best_model.pt` | ~17 MB | PyTorch checkpoint, ONNX is the production format |
| `server/admin/data/collected_samples.jsonl` | varies | Voice samples, already merged into `dataset.json` |

### Files Kept After Training

| File | Size | Why Keep? |
|------|------|-----------|
| `server/nlu/dataset.json` | ~500 KB | Merged dataset (needed for future retraining) |
| `server/nlu/model/nexus_nlu.onnx` | ~17 MB | Production ONNX model (used by NLU server) |
| `server/nlu/model/labels.json` | ~2 KB | Intent + slot label lists (used by NLU server) |
| `server/nlu/model/tokenizer/` | ~1 MB | BERT-Mini tokenizer files (used by NLU server) |
| `server/admin/data/approved_phrasings.jsonl` | varies | Brain-collected data (admin-only, for brain retraining) |
| `server/admin/data/rejected_examples.jsonl` | varies | Brain-collected rejections (admin-only) |

### Training Hyperparameters

| Parameter | Value | Description |
|-----------|-------|-------------|
| Model | `google/bert_uncased_L-2_H-128_A-2` | BERT-Mini, 2 layers, 128 hidden, 4.4M params |
| Max length | 64 tokens | Maximum input sequence length |
| Batch size | 16 | Mini-batch size |
| Epochs | 50 | Training epochs |
| Learning rate | 5e-5 | AdamW learning rate |
| Weight decay | 0.01 | L2 regularization |
| Warmup steps | 50 | Linear warmup before peak LR |
| Dropout | 0.1 | Dropout rate |
| Gradient clipping | 1.0 | Max gradient norm |
| Device | CPU | No GPU required |
| Seed | 42 | Reproducibility |

### Class Weighting

The training uses **inverse-frequency class weighting** to handle intent imbalance:

```python
weight = num_examples / (num_intents * count_for_intent)
weight = min(weight, 5.0)  # cap at 5x to avoid extreme values
```

This prevents dominant intents (e.g., `list_prs` with 80 examples) from overwhelming rare intents (e.g., `browser_new_tab` with 19 examples).

### Validation Split

The test set from `dataset.json` is split 50/50 into validation and test:
- **Validation** — used to select the best model (highest accuracy)
- **Test** — used for final accuracy reporting (never seen during training)

### Model Architecture

```
JointNLUModel
├── BERT-Mini (google/bert_uncased_L-2_H-128_A-2)
│   ├── Embeddings (128-dim, 30522 vocab)
│   ├── Layer 1 (128-dim, 2 attention heads)
│   └── Layer 2 (128-dim, 2 attention heads)
├── Intent Head: Linear(128 → 52)     ← [CLS] token → 52 intent logits
├── Slot Head: Linear(128 → 45)       ← all tokens → 45 slot logits each
└── Dropout(0.1)

Total parameters: ~4.4M
Model size (PyTorch): ~17 MB
Model size (ONNX): ~16.8 MB
```

### Loss Function

Joint loss = intent loss + slot loss:

- **Intent loss**: `CrossEntropyLoss(weight=class_weights)` — weighted for class imbalance
- **Slot loss**: `CrossEntropyLoss(ignore_index=0)` — ignores "O" (outside) tags so the model focuses on actual slot spans

## 5. `nexus build` — Bundle Model into Installer

After training, the model is synced to `src-tauri/resources/`. Running `nexus build` bundles it into the installer:

```bash
nexus train    # trains + syncs to resources/
nexus build    # bundles into installer.exe
```

The build process:
1. `syncNluModel()` copies ONNX + labels + tokenizer to `src-tauri/resources/server/nlu/model/`
2. Vite builds the frontend
3. Cargo builds the Rust binary (with `custom-protocol,admin-brain` features)
4. Tauri bundles everything in `resources/` into the installer

### Tauri Resources Config (`tauri.conf.json`)

```json
"resources": [
    "resources/server/nlu_server.py",
    "resources/server/nlu/requirements.txt",
    "resources/server/nlu/model/nexus_nlu.onnx",
    "resources/server/nlu/model/nexus_nlu.onnx.data",
    "resources/server/nlu/model/labels.json",
    "resources/server/nlu/model/tokenizer/*",
    ...
]
```

At runtime, the NLU server reads the model from:
```
exe_dir/resources/server/nlu/model/nexus_nlu.onnx
```

## 6. The BERT-Mini Model

### Why BERT-Mini?

| Model | Params | Size | Latency | Accuracy | RAM |
|-------|--------|------|---------|----------|-----|
| BERT-Tiny | 4.4M | 17 MB | ~2ms | Good | ~50 MB |
| **BERT-Mini** | **4.4M** | **17 MB** | **~3ms** | **Good** | **~50 MB** |
| BERT-Base | 110M | 420 MB | ~20ms | Excellent | ~450 MB |
| DistilBERT | 66M | 260 MB | ~10ms | Very Good | ~280 MB |

BERT-Mini was chosen because:
- **Small enough for CPU inference** — 3ms per prediction on a modern CPU
- **Low RAM** — 50 MB including ONNX Runtime
- **Good enough accuracy** — with proper training data, achieves >90% intent accuracy
- **Fast loading** — model loads in ~8-12 seconds (vs 30+ seconds for BERT-Base)
- **No GPU required** — runs on any laptop CPU

### Model Details

- **Architecture**: BERT (Bidirectional Encoder Representations from Transformers)
- **Layers**: 2 (vs 12 in BERT-Base)
- **Hidden size**: 128 (vs 768 in BERT-Base)
- **Attention heads**: 2 (vs 12 in BERT-Base)
- **Vocabulary**: 30,522 WordPiece tokens
- **Parameters**: ~4.4M
- **Pre-training**: Uncased English (same pre-training as BERT-Base, but smaller)
- **Fine-tuning**: Joint intent classification + slot filling (our task)

### ONNX Export

The PyTorch model is exported to ONNX for fast CPU inference:

```python
torch.onnx.export(
    model,
    (input_ids, attention_mask),
    "nexus_nlu.onnx",
    export_params=True,
    opset_version=14,
    input_names=["input_ids", "attention_mask"],
    output_names=["intent_logits", "slot_logits"],
    dynamic_axes={
        "input_ids": {0: "batch_size"},
        "attention_mask": {0: "batch_size"},
        "intent_logits": {0: "batch_size"},
        "slot_logits": {0: "batch_size"},
    },
)
```

- **Dynamic batch size** — supports batch=1 (runtime) and batch>1 (evaluation)
- **Opset 14** — compatible with ONNX Runtime 1.14+
- **max_length=64** — matches the training and inference tokenization

```json
  "train": [
```

```json
{
  "intents": ["open_app", "open_url", ..., "unknown"],
```

## 12. End-to-End Workflow

### For a New Contributor

```bash
# 1. Clone and setup (first time)
git clone <repo-url>
cd ULTRON
nexus install

# 2. Collect your voice samples (10-30 min)
#    Continuous mode: 3...2...1...SPEAK! → 2s record → auto-save → next
#    Groq key auto-loaded from NEXUS settings (no env var needed)
#    Press Ctrl+C to stop anytime
nexus collect

# 3. Retrain the model with your voice data (5-15 min)
#    → cleans up temp files automatically (~17 MB freed)
nexus train

# 4. Build the installer with the new model (5 min)
nexus build

# 5. Test the new model
nexus start
# Say: "type hello world", "press enter", "open whatsapp"
```

### For Quick Iteration (No Voice Collection)

```bash
# Just regenerate synthetic data + retrain (no mic needed)
# Temp files auto-deleted after training
nexus train

# Just clean the dataset (fix labels, dedup)
nexus train --clean-only

# Keep temp files for debugging (adds ~17 MB)
nexus train --keep-temp
```

### For the Admin (with Brain)

The admin's Qwen brain continuously collects approved/rejected phrasings in production:

```
server/admin/data/approved_phrasings.jsonl   ← brain auto-approves successful commands
server/admin/data/rejected_examples.jsonl    ← brain auto-rejects failed commands
```

When the admin runs `nexus train`, these are NOT automatically merged (they're handled by `merge_and_train.py` which is triggered by the brain monitor). But the admin can manually merge them:

```bash
# Merge brain-collected data + retrain
cd server/nlu
python merge_and_train.py

# Or use the unified pipeline (which reads collected_samples.jsonl)
nexus train
```

**Note:** `nexus train` only deletes `collected_samples.jsonl` (from `nexus collect`). It does NOT delete `approved_phrasings.jsonl` or `rejected_examples.jsonl` — those are brain-managed and kept for the brain's own retraining loop.

## 13. Advanced Usage

### Adding New Intents

1. Add the intent to `PHRASES` in `scripts/collect_nlu_samples.py`
2. Add the intent to `INTENTS` in `server/nlu/train.py`
3. Add the intent to `INTENTS` in `server/nlu/export_onnx.py`
4. Add the intent to `ALL_INTENTS` in `server/nlu_server.py`
5. Add the intent to `ALL_INTENTS` in `server/admin/brain_server.py`
6. Add a mapping in `nlu_to_parsed_intent()` in `src-tauri/src/nlu_client.rs`
7. Add the slot types to `SLOT_TYPES` in `train.py` and `export_onnx.py`
8. Run `nexus collect --intent <new_intent>` to collect voice data
9. Run `nexus train` to retrain
10. Run `nexus build` to bundle

### Adding New Slot Types

1. Add the BIO tags (`B-<name>`, `I-<name>`) to `SLOT_TYPES` in `train.py`
2. Add the same tags to `SLOT_TYPES` in `export_onnx.py`
3. Add slot extraction in `get_slots_for_intent()` in `collect_nlu_samples.py`
4. Add slot handling in `nlu_to_parsed_intent()` in `nlu_client.rs`
5. Retrain + rebuild

Edit `PHRASES` in `scripts/collect_nlu_samples.py` to add your own phrases:

## 14. Troubleshooting

### `nexus collect` Issues

#### "sounddevice not installed"

```bash
pip install sounddevice numpy scipy
# Or let nexus collect install it automatically:
nexus collect  # it will try to install deps first
```

#### "STT server not running on port 39217"

This is **not an error** — the collector uses **Groq cloud** as the primary transcription engine. The Groq API key is auto-loaded from your NEXUS `settings.json`. The STT server is only a fallback.

If you see this message, it means:
- NEXUS isn't running (STT server not started) — **fine, Groq will handle it**
- Groq key not found — check that you've configured Groq in NEXUS settings

If Groq is also unavailable:
```bash
# Option 1: Start NEXUS (runs STT server)
nexus start

# Option 2: Set GROQ_API_KEY manually
set GROQ_API_KEY=your_key_here
nexus collect
```

#### "Too quiet — did you speak?"

The RMS (volume) of your recording was below 0.005. This means:
- Your microphone volume is too low
- You're too far from the mic
- You didn't speak during the 4-second window
- The mic is muted

Fixes:
- Move closer to the microphone (30-50cm)
- Increase microphone volume in Windows Sound settings
- Unmute the microphone
- Speak louder

#### "Transcribed: '' (empty)"

The STT server returned an empty transcription. This means:
- The audio was too quiet for STT to detect speech
- The audio was all noise (no speech detected)
- STT hallucination filter caught a false positive

Fix: Retry the recording, speak clearly and at normal volume.

### `nexus train` Issues

#### "torch not found" / "transformers not found"

```bash
pip install -r server/nlu/requirements-train.txt
```

#### "CUDA out of memory"

The training runs on CPU by default. If you have a GPU and want to use it, edit `train.py`:

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
```

But CPU training is fine — BERT-Mini is small enough that 50 epochs take ~5-10 minutes on CPU.

#### "Training accuracy is low"

Possible causes:
- **Dataset has malformed labels** — run `nexus train --clean-only` first
- **Not enough examples per intent** — collect more with `nexus collect`
- **Class imbalance** — the class weighting should handle this, but if one intent has <10 examples, it may not learn well
- **STT distortions not covered** — collect real voice samples to capture how STT mishears commands

#### "ONNX export fails with dimension mismatch"

Make sure `max_length=64` in `export_onnx.py` matches `MAX_LEN = 64` in `train.py` and `MAX_LEN = 64` in `nlu_server.py`. All three must be the same.

#### "NLU server returns Internal Server Error"

Check the server logs. Common causes:
- **Missing ONNX model** — run `nexus train` to export it
- **Missing tokenizer** — copy tokenizer to model dir
- **Dimension mismatch** — ONNX was exported with wrong max_length (see above)
- **Missing labels.json** — run `nexus train` to generate it

### `nexus build` Issues

#### "NLU model not found"

```bash
# Train and sync first
nexus train
# Then build
nexus build
```

#### "Model not bundled in installer"

Check `tauri.conf.json` has the resources listed:

```json
"resources/server/nlu/model/nexus_nlu.onnx",
"resources/server/nlu/model/labels.json",
"resources/server/nlu/model/tokenizer/*",
```

And check the model exists in resources:

```bash
ls src-tauri/resources/server/nlu/model/
# Should show: labels.json  nexus_nlu.onnx  tokenizer/
```

#### "best_model.pt not found" / "I want to retrain but temp files were deleted"

After `nexus train` completes, `best_model.pt` is deleted to save space. To retrain:

```bash
nexus train    # regenerates best_model.pt from scratch (full pipeline)
```

If you only want to re-export ONNX without retraining (and `best_model.pt` was deleted), you must retrain — the PyTorch checkpoint is the source. Use `--keep-temp` next time if you want to keep it:

```bash
nexus train --keep-temp    # keeps best_model.pt + new_examples.json + collected_samples.jsonl
```

#### "collected_samples.jsonl was deleted — can I recover my voice data?"

No — after merge, the voice samples are in `dataset.json`. The JSONL file is deleted to save space. Your data is not lost — it's part of the dataset now. To see it:

```bash
python -c "import json; data=json.load(open('server/nlu/dataset.json')); train=data.get('train',data); print(f'{len(train)} total examples')"
```

If you want to keep the raw JSONL for reference, use `--keep-temp` or back it up before training:

```bash
cp server/admin/data/collected_samples.jsonl ~/my_voice_samples_backup.jsonl
nexus train
```

## 15. Admin-Only Brain Integration

The admin-only Qwen brain continuously monitors commands and collects training data:

### Automatic Data Collection (Admin Only)

```
Administrator speaks a command
    ↓
STT transcript
    ↓
Deterministic parser  →  BERT-Mini NLU  →  Qwen brain (observes)
    ↓
Command executes
    ↓
    ├── SUCCESS → brain auto-approves → approved_phrasings.jsonl
    ├── FAILURE → brain auto-rejects → rejected_examples.jsonl
    └── Admin says "wrong" → brain marks last command as bad
    ↓
Next retrain: good examples added, bad examples removed
    ↓
BERT-Mini gets BETTER and never repeats mistakes
```

### Brain Data Files (Gitignored, Admin-Only)

| File | Source | Purpose |
|------|--------|---------|
| `server/admin/data/approved_phrasings.jsonl` | Brain monitor (auto) | Successful command phrasings |
| `server/admin/data/rejected_examples.jsonl` | Brain monitor (auto) | Failed/wrong command phrasings |
| `server/admin/data/collected_samples.jsonl` | `nexus collect` (manual) | Voice-collected samples |
| `server/admin/data/pronunciation_map.json` | Brain server | STT pronunciation corrections |

### Brain-Triggered Retraining

When 50 new approved phrasings are collected, the brain monitor triggers `merge_and_train.py`:

1. Read `approved_phrasings.jsonl` (good examples)
2. Read `rejected_examples.jsonl` (bad examples — to REMOVE)
3. Merge good into dataset, remove bad (with fuzzy matching)
4. Retrain BERT-Mini
5. Compare new vs old accuracy
6. Hot-swap if new >= old, rollback if new < old
7. Clear approved/rejected files

This is **separate** from `nexus train` — it runs automatically in the background on the admin's laptop. `nexus train` is for manual/contributor retraining.
